# 个人博客系统 - HR面试问答手册

## 项目基础问题

### Q1: 请介绍一下你的博客项目
**标准回答**:
这是一个我独立开发的全栈博客内容管理系统，前端使用Vue3+TypeScript，后端采用Node.js+Express，数据库使用MySQL。项目支持多用户角色管理、富文本编辑、文件上传、评论系统等完整功能。整个开发周期大约3个月，目前已完成核心功能并可正常部署使用。

**深入展开**: 
- 技术选型理由：Vue3的组合式API提高了代码复用性，TypeScript增强了类型安全
- 项目规模：前端约50个组件，后端20+个API接口，8张数据库表
- 解决的问题：个人知识管理和分享需求，同时作为技术能力展示平台

### Q2: 为什么选择这些技术栈？
**标准回答**:
- **Vue3**: 相比Vue2性能提升明显，组合式API让逻辑复用更清晰，生态成熟
- **TypeScript**: 大型项目必备，编译时错误检查，提高代码质量和开发效率
- **Vite**: 开发时热更新速度快，构建工具配置简单
- **Pinia**: 比Vuex更简洁的状态管理，TypeScript支持更好
- **Node.js**: JavaScript全栈开发，学习成本低，npm生态丰富
- **MySQL**: 关系型数据库，ACID特性保证数据一致性，适合博客的关联查询需求

**技术对比分析**:
- 考虑过React，但Vue的模板语法更直观，开发效率更高
- 选择Express而非Koa，因为中间件生态更丰富，文档更完善

### Q3: 项目开发周期和计划是怎样的？
**标准回答**:
总开发周期3个月，分为4个阶段：
1. **需求分析和架构设计** (1周): 梳理功能需求，设计数据库ER图，确定技术架构
2. **后端API开发** (4周): 搭建基础框架，实现用户认证、文章管理、评论系统等核心API
3. **前端界面开发** (6周): 组件开发、页面布局、状态管理、路由配置
4. **测试和部署优化** (1周): 功能测试、性能优化、Docker容器化部署

**项目管理方式**: 使用Git进行版本控制，按功能模块分支开发，定期code review

## 技术深度问题

### Q4: 你的权限控制是如何设计的？
**标准回答**:
采用RBAC (基于角色的访问控制) 模型：
- **角色层级**: 超级管理员 > 管理员 > 编辑 > 作者，权限逐级递减
- **前端控制**: Vue Router路由守卫，根据用户角色动态显示菜单和页面
- **后端验证**: JWT中间件验证身份，权限中间件检查操作权限
- **数据库设计**: users表存储角色信息，通过枚举字段控制权限等级

**安全措施**:
```javascript
// 示例：后端权限中间件
const requireAuth = (roles) => (req, res, next) => {
  const userRole = req.user.role
  if (!roles.includes(userRole)) {
    return res.status(403).json({ message: '权限不足' })
  }
  next()
}
```

### Q5: 富文本编辑器的图片上传是如何处理的？
**标准回答**:
这是项目的一个技术亮点，解决了多个复杂问题：

**1. 去重机制**: 前端计算文件SHA256哈希，避免重复上传相同图片
**2. 多种上传方式**: 支持拖拽、粘贴、点击上传，还能自动识别粘贴的base64图片
**3. 预览优化**: 上传后的图片先显示预览地址，再异步转换为blob URL避免401错误
**4. 智能删除**: 支持键盘删除和Alt+点击删除，通过DOM操作精确定位并删除对应的Markdown引用

**技术实现细节**:
```javascript
// 示例：图片去重上传逻辑
async function handleImageUpload(file) {
  const hash = await calculateSHA256(file)
  const existing = await lookupAttachmentByHash(hash)
  if (existing) {
    return existing.attachmentId // 复用已存在的图片
  }
  return await uploadAttachment(file) // 上传新图片
}
```

### Q6: 数据库设计有什么特色？
**标准回答**:
采用规范化设计，主要特点：

**1. 核心表结构**:
- `users`: 用户信息，支持多种登录方式
- `posts`: 文章主表，包含状态管理和SEO字段  
- `comments`: 评论表，支持楼中楼回复
- `categories/tags`: 分类标签，多对多关联
- `attachments`: 附件表，统一管理上传文件
- `post_revisions`: 版本控制，支持历史回滚
- `operation_logs`: 操作日志，完整审计追踪

**2. 设计亮点**:
- 软删除机制保护重要数据
- 外键约束保证数据一致性
- 合理索引提升查询性能
- 枚举字段控制状态流转

### Q7: 如何保证系统的安全性？
**标准回答**:
实施了多层安全防护：

**1. 认证授权安全**:
- JWT Token有效期控制，支持自动刷新
- 密码BCrypt加密存储
- 登录失败次数限制

**2. 输入验证**:
- 前端表单校验 + 后端参数验证双重保护
- SQL参数化查询防注入
- XSS过滤处理用户输入

**3. 接口安全**:
- CORS跨域控制
- 请求频率限制防止暴力攻击
- 敏感操作日志记录

**4. 文件上传安全**:
- 文件类型白名单验证
- 文件大小限制
- 上传路径控制防止目录遍历

## 问题解决能力问题

### Q9: 开发过程中遇到的最大技术难点是什么？
**标准回答**:
最大的难点是富文本编辑器与Vue3的深度集成。

**问题背景**: Vditor编辑器基于原生DOM操作，与Vue的响应式系统存在冲突，特别是图片上传后的预览更新问题。

**解决过程**:
1. **问题分析**: 发现编辑器内的图片预览地址会因为鉴权问题显示403错误
2. **方案设计**: 设计了预览地址到blob URL的转换机制
3. **技术实现**: 
   - 监听DOM变化，自动识别预览地址的图片
   - 异步获取图片二进制数据，生成本地blob URL
   - 建立缓存机制避免重复请求
   - 组件销毁时清理blob URL防止内存泄漏

**收获**: 深入理解了DOM操作与Vue响应式的边界，提升了复杂组件封装能力。

## 项目管理问题

### Q12: 你是如何保证项目进度的？
**标准回答**:
采用了敏捷开发的思路：

**1. 功能分解**: 将大功能拆分为可独立开发的小模块，每个模块2-3天完成
**2. 优先级排序**: 先实现核心功能（用户登录、文章发布），再开发增值功能（评论、后台管理）
**3. 迭代开发**: 每周完成一个可用版本，及时发现和解决问题
**4. 风险控制**: 技术难点优先攻克，预留20%的时间缓冲

**时间管理技巧**:
- 使用番茄工作法保持专注
- 复杂问题先画图理清思路再编码
- 每日总结进度和问题，调整次日计划

## 面试技巧

### 💡 回答要点
1. **结构化表达**: 先总结后展开，逻辑清晰
2. **数据支撑**: 用具体数字说明项目规模和效果
3. **技术深度**: 不只说用了什么技术，更要说为什么这样选择
4. **问题导向**: 重点讲解决了什么问题，如何解决的
5. **成长收获**: 体现学习能力和技术成长

### ⚠️ 注意事项
1. **不要夸大**: 诚实说明项目规模，不要过度包装
2. **准备细节**: 对项目的每个技术点都要能深入展开
3. **展示思考**: 体现技术选型的思考过程，而非盲目跟风
4. **承认不足**: 坦诚项目的局限性，并说明改进方向
5. **保持谦逊**: 强调学习态度，避免过于自信的表达
