# 项目修复清单

更新时间：2026-04-10

## 1. 编码与乱码

### 已处理
- 仓库根目录新增 `.editorconfig`，统一代码、文档、SQL、环境文件使用 UTF-8。
- 复查 `backend/backend`、`fontend/src`、`docs` 下的活跃文本源码，按 UTF-8 严格读取，未发现大面积无效编码字节。

### 继续执行
- 所有新文件统一使用 UTF-8 保存，不混用 ANSI、GBK、UTF-8 with BOM。
- 导入 SQL 时明确选择 `utf8mb4`，Navicat 或命令行都不要使用系统默认编码。
- Windows 本地编辑器统一设置为 UTF-8，避免“文件本身没坏，编辑器显示乱码”的误判。
- 不直接修改 `dist/`、`uploads/` 里的产物文件。

### 验收标准
- `backend/backend`、`fontend/src`、`docs` 下文本文件均可按 UTF-8 正常打开。
- 页面文案、Swagger 注释、SQL 注释、环境配置注释不再出现乱码。

## 2. P0 阻断项

- 修复找回密码接口，必须引入邮箱或短信验证码校验，禁止仅凭邮箱或手机号直接重置密码。
- 关闭文章详情和编辑器预览中的 XSS 风险，禁止未净化 HTML 直接进入 `v-html`。
- 停止把登录 token 长期放在 `localStorage`，改为更安全的会话方案。
- 禁止游客通过 `status` 参数枚举草稿、归档文章和未审核评论。
- 关闭公开附件预览、下载、详情、查重探测对未授权用户的暴露。
- 受管附件不再直接暴露 `/uploads` 静态路径，统一经 `/api/attachments/{id}/preview` 或 `/download` 控制访问。
- 生产环境默认关闭 `/api-docs`，仅在显式设置 `ENABLE_API_DOCS=true` 时开放。
- 移除仓库中的真实 SMTP、数据库、JWT 敏感配置，立即更换已泄露凭据。

## 3. P1 高优先级修复

- 注册接口禁止客户端自带 `roleIds` 提权。
- 登录和鉴权流程增加 `IsActive` 校验，禁用用户不能登录，已有 token 也要失效。
- `logout` 改为真实退出，至少补充 token 撤销或会话失效机制。
- 上传和导入接口增加服务端文件大小、类型、后缀白名单校验。
- 关闭公开 Redis 调试接口，至少要求管理员权限。
- 统一错误响应语义，业务错误不要再返回 HTTP 200。
- `/api/redis` 管理接口失败分支显式区分 400/404/429/503/500，避免默认 400 混淆真实故障语义。

## 4. P2 结构与一致性

- 清理 `articleController.js` 中的重复导出和重复实现。
- 前后端角色模型对齐，删除前端里不存在于数据库的 `superadmin` 假角色。
- 后台“系统设置”接口补齐后端实现，去掉当前前端 404 兜底假流程。
- 角色权限管理接口补齐真实持久化逻辑，不能只返回成功。
- 附件去重逻辑统一以服务端最终文件哈希为准，避免查重和落库不一致。
- 审查并统一中英文返回消息，避免同一模块接口风格混乱。

## 5. 链路验收清单

### 用户链路
- 注册：普通用户注册后只能拿到默认角色。
- 登录：禁用用户、错误密码、过期 token 都能正确拦截。
- 找回密码：错误验证码、过期验证码、重复使用验证码都失败。
- 登出：退出后旧 token 无法继续访问受保护接口。

### 文章链路
- 游客只能看到 `published` 文章列表和详情。
- 作者只能编辑自己的草稿和文章。
- 点赞、收藏状态从数据库真实读取，不走前端示例数据。
- 非公开文章不能被 `slug`、`id`、列表、计数、分类/标签公共接口绕过读取。

### 评论链路
- 游客只能读取已审核评论。
- 登录用户可发表评论、回复、删除自己的可删评论。
- 管理员可审核评论状态，前台审核状态同步正确。

### 附件链路
- 未登录用户不能探测、预览、下载私有附件。
- 临时附件只能被上传者和目标文章流程访问。
- 非白名单文件上传失败，超限文件上传失败。
- 头像、首页猫猫图片、附件、文档导入入口都要在 multer 层拦截非法扩展名 / MIME 和超限文件。

### 后台链路
- `editor`、`author`、`admin` 的页面权限和接口权限一致。
- 用户管理、角色管理、日志管理、设置管理都走真实后端接口。
- 所有关键操作写入操作日志。

## 6. 执行顺序

1. 先处理编码和敏感信息，确保后续改动不再污染仓库。
2. 再修账号安全、XSS、附件暴露、游客越权这四个阻断项。
3. 然后统一权限模型、错误语义、后台真实接口。
4. 最后做控制器去重、体验优化和功能扩展。

## 7. 最低验证要求

- 前端至少执行一次 `npm run build`。
- 后端至少验证用户、文章、评论、附件四条主链路各一条成功路径和一条失败路径。
- SQL 导入前确认客户端编码为 `utf8mb4`。
- 新增或修改文档后，用 UTF-8 打开原文件复查一次，确认没有新乱码。
