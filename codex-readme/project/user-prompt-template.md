# 用户提示模板

把下面模板作为任务输入时，优先填真实路径和真实风险，不要写成空泛需求。

```text
任务：
- 我要解决：

目标路径：
- 主要修改目录：
- 明确不要改的目录：

相关契约：
- 会影响的接口 / 数据表 / 环境变量 / 上传路径 / 缓存键：
- 已知消费者：

风险级别：
- 是否涉及登录 / 权限 / 文章公开态 / 评论审核 / 附件 / Redis / 部署：

验收：
- 我期望看到的成功结果：
- 至少一个必须覆盖的失败路径：

验证偏好：
- 可以执行的命令：
- 需要人工说明的页面或接口：

额外限制：
- 是否允许改文档：
- 是否允许改 SQL / Docker / Nginx / 环境变量模板：
```

## 适配当前仓库的提示

- 如果任务在 `fontend/`，最好写清楚对应页面、路由或 `src/api/` 模块。
- 如果任务在 `backend/backend/`，最好写清楚对应 route / controller / model。
- 如果任务跨前后端，明确哪个 API 或会话契约是共享边界。
- 如果无法确认某个事实，请显式写“假设”，不要把猜测伪装成现状。
